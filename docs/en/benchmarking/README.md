# Benchmarks

This page collects the supported benchmark entrypoints and the canonical ways
to run them. For a source-tree map of benchmark code, see
[`benchmark/README.md`](../../../benchmark/README.md).

## Benchmark Inventory

The repo currently has benchmark coverage beyond multimodal. Treat this table
as the routing map for choosing the right runner; keep actual result claims tied
to the output artifacts generated by each run.

| Area | Entry point | Scope and notes |
| --- | --- | --- |
| Efficiency and throughput | [`efficiency.md`](efficiency.md) | Matched Sparse-Engine/vLLM length, concurrency, churn, TP, latency, throughput, and directly sampled GPU-activity suite. |
| Sparse-Engine microbenchmark | `benchmark/microbench.py` | Synthetic prompt-length engine throughput, TTFT, prefill/decode throughput, ITL, and GPU memory. |
| Simulated Deep Research | [`simulated-deep-research.md`](simulated-deep-research.md) | Synthetic 10-round main-agent/subagent serving workload through the non-uniform smart router. |
| Max-batch throughput | `scripts/benchmarks/run_sparseengine_max_batch_throughput.py` | Capacity-oriented Sparse-Engine stress/throughput runs. |
| LongBench | `benchmark/long_bench/pred.py`, `benchmark/long_bench/eval.py` | Native Sparse-Engine runner; use `--task` for subsets and omit it for the full suite. |
| MathBench, AIME, MATH-500 | `benchmark/math_bench/pred.py`, `benchmark/math_bench/eval.py` | Native Sparse-Engine runner for `gsm8k`, `aime2024`, `math500`, and `hmmt_nov`. |
| SCBench | `benchmark/scbench/run_scbench.py`, `benchmark/scbench/run_scbench_preprocessed.py`, `benchmark/scbench/compute_scores.py`, `benchmark/scbench/run_kvzip_preprocessed.py` | Shared-context benchmark routes for repo-owned runs plus upstream SCBench baselines. |

## Throughput Benchmark

Use `benchmark/microbench.py` to measure TTFT, prefill throughput, decode
throughput, ITL, and GPU memory across synthetic prompt lengths.

Notes:

- Prefer `--hyper_params` to pass Sparse-Engine settings as a JSON object.
- `--hyper_params` accepts canonical runtime names such as `sparse_method`,
  `engine_prefill_chunk_size`, and `decode_keep_tokens`.
- `--lengths` measures prompt length; the script sets
  `max_model_len = length + output_len + 100` internally.

Baseline:

```bash
python benchmark/microbench.py \
  --model_path <PATH_TO_BASE_MODEL> \
  --lengths 512000 \
  --batch_sizes 2 \
  --methods vanilla \
  --hyper_params '{"gpu_memory_utilization": 0.9}' \
  --output_dir benchmark/results/microbench/vanilla_512k
```

The old `scripts/benchmarks/bench_sparse_engine.py` path remains as a
compatibility wrapper for existing runbooks and regression harnesses.

## MathBench With Sparse-Engine

These examples are convenient for GSM8K, AIME 2024, MATH-500, and HMMT-style
comparisons while exercising the Sparse-Engine engine directly. For dataset
details, see
[`benchmark/math_bench/README.md`](../../../benchmark/math_bench/README.md).

Full-attention baseline:

```bash
python benchmark/math_bench/pred.py \
  --model qwen7b-full \
  --model_path <MODEL_ROOT>/DeepSeek-R1-Distill-Qwen-7B \
  --tokenizer_path <MODEL_ROOT>/DeepSeek-R1-Distill-Qwen-7B \
  --ws 1 \
  --batch_size 30 \
  --task aime2024 \
  --temperature 0.6 \
  --hyper_param '{"engine_prefill_chunk_size": 4096, "sparse_method": "vanilla"}'
```

OmniKV:

```bash
python benchmark/math_bench/pred.py \
  --model qwen7b-omnikv \
  --model_path <MODEL_ROOT>/DeepSeek-R1-Distill-Qwen-7B \
  --tokenizer_path <MODEL_ROOT>/DeepSeek-R1-Distill-Qwen-7B \
  --ws 1 \
  --batch_size 30 \
  --task aime2024 \
  --temperature 0.6 \
  --hyper_param '{"engine_prefill_chunk_size": 4096, "sparse_method": "omnikv", "full_attention_layers": "0,1,2,4,7,14", "decode_keep_tokens": 1024}'
```

DeltaKV requires a compressor trained for the same base model. Replace the
checkpoint path below with a matching compressor for the model you run.

```bash
python benchmark/math_bench/pred.py \
  --model qwen7b-deltakv \
  --model_path <MODEL_ROOT>/DeepSeek-R1-Distill-Qwen-7B \
  --tokenizer_path <MODEL_ROOT>/DeepSeek-R1-Distill-Qwen-7B \
  --ws 1 \
  --batch_size 30 \
  --task aime2024 \
  --temperature 0.6 \
  --hyper_param '{"engine_prefill_chunk_size": 512, "max_num_batched_tokens": 8192, "max_num_seqs_in_batch": 30, "sparse_method": "deltakv", "full_attention_layers": "0,1,2,4,7,14", "decode_keep_tokens": 1024, "deltakv_checkpoint_path": "<CHECKPOINT_ROOT>/<MATCHING_COMPRESSOR_DIR>", "deltakv_latent_dim": 256, "deltakv_latent_quant_bits": 4, "full_layer_kv_quant_bits": 4, "enable_full_layer_kivi_quant": true}'
```

Method selection happens through `sparse_method` and checkpoints through
`deltakv_checkpoint_path`.

To include multiple math tasks in one run, pass a comma-separated `--task`
value such as `gsm8k,aime2024,math500`. Use `--num_samples` only for smoke
runs, and do not mix smoke-only rows into final benchmark tables.

## LongBench With Sparse-Engine

This entrypoint runs LongBench through the native Sparse-Engine engine.

```bash
python benchmark/long_bench/pred.py \
  --model qwen7b-omnikv \
  --model_path <MODEL_ROOT>/Qwen2.5-7B-Instruct-1M \
  --tokenizer_path <MODEL_ROOT>/Qwen2.5-7B-Instruct-1M \
  --ws 1 \
  --batch_size 1 \
  --task qasper,hotpotqa,multi_news \
  --hyper_param '{"engine_prefill_chunk_size": 4096, "sparse_method": "omnikv", "decode_keep_tokens": 2048, "full_attention_layers": "0,1,2,4,7,14", "recent_keep_tokens": 128, "sink_keep_tokens": 8}'
```

For a full LongBench run, omit `--task`. To switch to DeltaKV, set
`sparse_method="deltakv"` plus a matching
`deltakv_checkpoint_path`. Legacy `deltakv-less-memory*` method ids in old
manifests normalize to the same runtime.

For linear chain prefix-cache traces, select `chain_snapkv`, `chain_h2o`,
`chain_pyramidkv`, `chain_rkv`, or `chain_skipkv` in
`scripts/benchmarks/bench_prefix_cache.py`. Chain cases require
`--workloads multiturn --history_update generated`: turn 0 records the
server-created `chain_id`, later turns reuse it, and each record includes chain
status, reused logical tokens, prefilled delta tokens, and per-layer physical
residency. A tombstone or digest mismatch is a failed sample; the harness does
not fall back to recomputation.

## SCBench

SCBench lives under `benchmark/scbench/`. Use `run_scbench.py` for standard
SCBench generation, `run_scbench_preprocessed.py` for preprocessed SCBench
inputs, `run_kvzip_preprocessed.py` for KVZip preprocessed comparisons, and
`compute_scores.py` for scoring generated prediction files.

```bash
python benchmark/scbench/run_scbench.py \
  --task scbench_qa_eng \
  --model_name_or_path <MODEL_ROOT>/Qwen2.5-7B-Instruct-1M \
  --data_dir <SCBENCH_DATA_DIR> \
  --output_dir <OUTPUT_ROOT>/scbench \
  --attn_type dense \
  --kv_type dense \
  --ws 1 \
  --max_seq_length 131072 \
  --use_chat_template \
  --trust_remote_code
```

Notes:

- SCBench uses the native `sparseengine` attention type for Sparse-Engine methods.
  Pass the method, checkpoint, and keep budgets through `--hyper_param`.
- `compute_scores.py` constructs prediction paths from the generated model tag.
  Inspect the runner output directory before batch scoring rather than assuming
  a manually chosen path layout.
- `--num_eval_examples`, `--start_idx`, `--stop_idx`, shard options, and
  context-length filters are for partial/smoke runs. Label those outputs as
  partial when documenting results.
- `benchmark/scbench/run_kvzip_preprocessed.py` is the route for KVZip
  preprocessed artifacts; do not substitute it for raw SCBench predictions
  without stating the preprocessing source.

## Claw-Eval

Use `benchmark/claw_eval/run_sparseengine_claw_eval.sh` when evaluating a
Sparse-Engine model through Claw-Eval. The script prepares or updates an external
`claw-eval` checkout, optionally starts
`sparseengine.entrypoints.openai.api_server`, validates the Docker sandbox,
renders a Claw-Eval config, and writes a run manifest.

```bash
OPENROUTER_API_KEY=<KEY> \
MODEL_PATH=<MODEL_ROOT>/Qwen2.5-7B-Instruct-1M \
CUDA_VISIBLE_DEVICES=0 \
ENGINE_KWARGS='{"tensor_parallel_size":1,"gpu_memory_utilization":0.88,"max_model_len":131072,"engine_prefill_chunk_size":4096,"sparse_method":"vanilla"}' \
CLAW_EVAL_ARGS='batch --config ${CLAW_EVAL_CONFIG} --sandbox --trials 3 --parallel 1' \
bash benchmark/claw_eval/run_sparseengine_claw_eval.sh
```

To use an OpenAI-compatible server that is already running, disable the
managed server and provide both its API base URL and health endpoint:

```bash
START_SPARSEENGINE_SERVER=0 \
SPARSEENGINE_OPENAI_BASE_URL=http://127.0.0.1:18000/v1 \
SERVER_HEALTH_URL=http://127.0.0.1:18000/health \
SPARSEENGINE_OPENAI_API_KEY=local-sparseengine \
SPARSEENGINE_CLAW_MODEL_ID=sparseengine-claw \
CLAW_EVAL_ARGS='batch --config ${CLAW_EVAL_CONFIG} --sandbox --no-judge --trials 1 --parallel 1' \
bash benchmark/claw_eval/run_sparseengine_claw_eval.sh
```

Notes:

- `--sandbox` requires a running Docker daemon and a usable sandbox image.
  The runner starts a preflight container and verifies `/health`, `/exec`, and
  grader isolation before evaluation. It reuses `claw-eval-agent:latest` by
  default. If the image is absent, set `CLAW_EVAL_BUILD_SANDBOX_IMAGE=1` to
  build it explicitly; the runner never starts a large image build silently.
- Set `CLAW_EVAL_SANDBOX_IMAGE` to use another image. An explicit
  `--sandbox-image` in `CLAW_EVAL_ARGS` takes precedence. Optional additional
  `docker build` arguments can be passed through
  `CLAW_EVAL_DOCKER_BUILD_ARGS`.
- Set `CLAW_EVAL_UPDATE_REPO=0` to reuse an existing, pinned external checkout
  without fetching or changing it. The resolved Claw-Eval commit and sandbox
  image ID/size are saved in `run_manifest.json`. The checkout must be clean;
  local source changes fail before evaluation.
- The shared OpenAI-compatible server is intentionally text-only for this
  benchmark route. Unsupported OpenAI request fields fail instead of being
  silently ignored. Set `CLAW_EVAL_TEXT_ONLY=1` to build a recorded task view
  that excludes `multimodal` tasks and tasks exposing image, PDF, presentation,
  or spreadsheet files. Exclusions are retained as `skipped_by_policy` rows in
  `per_sample_results.jsonl`; evaluated and skipped counts remain separate in
  `final_summary.json`.
- `CLAW_EVAL_ARGS` must contain exactly one explicit `--parallel`. For a
  managed server, the runner sets `max_decoding_seqs` to
  `parallel / SPARSEENGINE_DATA_PARALLEL_SIZE` and rejects non-divisible values.
  `max_num_seqs_in_batch` remains an independent prefill batching control.
- To continue an interrupted run in the same `RUN_NAME`, set
  `CLAW_EVAL_RESUME_TRACE_DIR` to that run's concrete trace subdirectory. The
  runner records the path and passes Claw-Eval's bounded `--continue` mode;
  resume paths outside the current run are rejected.
- Remote launchers can keep a reverse port forward alive with
  `benchmark/ssh_reverse_tunnel.sh`. It uses SSH keepalives, records each
  reconnect, and stops after the configured reconnect bound instead of hiding
  a permanently broken route.
- Use `SETUP_ONLY=1` to prepare the external repo, environments, Docker
  preflight, config, engine kwargs file, and run manifest without launching
  the model server or benchmark. A model path is not required in setup-only or
  external-server mode.
- `OPENROUTER_API_KEY` is required for judge-enabled runs. Development smoke
  runs may pass `--no-judge`, but those scores are not official leaderboard
  results. Official Claw-Eval uses three trials and Pass^3.
- The wrapper validates the batch artifacts produced by the current invocation.
  A low task score is a valid evaluation result, but a missing result, malformed
  trial, or task-level error makes the wrapper exit nonzero. Raw upstream files,
  normalized `per_sample_results.jsonl`, and `final_summary.json` remain in the
  run directory for diagnosis.
- Default outputs go under
  `<OUTPUT_ROOT>/claw-eval/<RUN_NAME>/`; override `OUTPUT_ROOT` or
  `RUN_NAME` when needed.

## RULER Core And Standalone NIAH

`benchmark/ruler_vt/pred.py` is the self-contained RULER core runner. It supports
`niah_single_1`, `niah_multikey_2`, `vt`, `cwe`, and `fwe`; pass one with
`--task`. The task contracts and prompts follow
[NVIDIA RULER](https://github.com/NVIDIA/RULER), while deterministic synthetic
word pools replace its optional `wonderwords` and large word assets.
These artifacts are suitable for Sparse-Engine regression comparisons, but are not
official leaderboard datasets. Essay-based NIAH and `qa_1`/`qa_2` remain out of
scope because they require downloaded external corpora.
It generates `dataset.jsonl`, saves raw outputs, parsed outputs, per-sample
results, `run_info.json`, and `aggregate_metrics.json`.

```bash
python benchmark/ruler_vt/pred.py \
  --task vt \
  --model-path <MODEL_ROOT>/Qwen2.5-7B-Instruct-1M \
  --output-dir <OUTPUT_ROOT>/ruler_vt/qwen25_7b_vanilla \
  --sparse-method vanilla \
  --context-lengths 4096,8192,16384 \
  --samples-per-length 20 \
  --hyper-param <ENGINE_PARAMS_JSON>
```

For a prefix-cache correctness check, set `enable_prefix_caching=true` in the
engine params and add `--allow-prefix-caching --prefix-cache-replay
--require-prefix-cache-hit`. Each deterministic batch is immediately replayed;
the runner requires nonzero hit requests/tokens and exact output equality.
Use the regression harness below for matched vanilla comparison and per-length
quality grades.

`benchmark/niah/test_niah.py` is the needle-in-a-haystack utility runner. It can
generate synthetic data online or load a JSONL file with `--online_test=False`.

```bash
python benchmark/niah/test_niah.py \
  --model_path <MODEL_ROOT>/Qwen2.5-7B-Instruct-1M \
  --tokenizer_path <MODEL_ROOT>/Qwen2.5-7B-Instruct-1M \
  --sparse_method vanilla \
  --output_path niah/qwen25_7b_vanilla \
  --context_lengths 16,32,64
```
